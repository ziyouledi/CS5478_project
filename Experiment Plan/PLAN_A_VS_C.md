## 一、已锁定的共同实验底座（A 与 C 完全共享，保证严格公平对比）

基于前序已完成的实验，A 和 C 共享以下已验证的固定底座：

1. **底层技能控制器**：冻结的 **`Unified v4 Expert` (`expert-unified-v4-seed0.pth`)**
   - 已在 P2.1 (`1169489`) 中证明：在 96 个离散状态（24 朝向 $\times$ 4 卡位）上，Closed-loop 与 Open-loop BFS Oracle 成功率均为 **100.0%（2048/2048 回合，0 跌落，0 铰链误带动）**，每步宏动作平均仅需 **16.5 个控制步（0.27 秒）**；目标达成后原地保持 240 步（4 秒）**0 跌落**。
   - **含义**：底层技能损失为 0（$P_{\text{Oracle}} = 1.000$），上层模型的任何失败 100% 归因于**规划错**或**感知错**。
2. **统一的状态与目标语义表示**：采用 **杠杆 1 `relational`（颜色空间邻接关系，去掉人造数字 `detent = 0..3`）**
   - 状态由 3 个可观测几何属性唯一确定：
     - `up`：朝上（$+z$）的面颜色；
     - `front`：朝前（$+x$，面向主相机 `c1`）的面颜色；
     - `strips_on_base`（或 `red_strip`）：下层 2/3 各侧面（红/绿/黄/蓝）正上方紧挨着的顶层 1/3 窄带颜色。
   - **为什么不用 `numeric` (`detent=0..3`)？**
     - `1169531` vs `1169616` 已实测证明：给 `detent` 数字会让规划退化为简单模 4 减法（零样本 $L=3, 4$ 高达 68% / 56%）；而改为真实可见的 **`relational` 颜色关系** 后，零样本 Greedy 在 $L=1, 2, 3, 4$ 上呈完美阶梯衰减（**100% $\to$ 56% $\to$ 14% $\to$ 4%**），同时 $G=8$ 采样的 **GRPO 有效组比例在 $L=2, 3, 4$ 上高达 60% / 66% / 54%**！
3. **统一的动作空间与物理合法性约束**：
   - 每轮输出一个 JSON 宏动作：
     - `{"action": "reorient", "up": "<colour>", "front": "<colour>"}`（任意正交颜色对，1 轮到位）；
     - `{"action": "turn", "delta": "+90" | "-90"}`（**仅当 `current.up == "white"` 时合法**；若 `up != "white"` 时发出则记为 `illegal_turn_not_white`，消耗 1 轮且状态不变）。
4. **统一的评估任务集**：
   - 复用 `1169616` 冻结的 200 个分层测试任务（$L \in \{1, 2, 3, 4\}$ 各 50 个任务，最多 $2L+2$ 轮），所有训练均在独立的训练集状态对上进行（严禁泄露测试集起终点对）。

## 三、方案 A 详细实验计划（纯文本关系状态规划：Pure GRPO vs. SFT）

如果执行方案 A，目标是**在完全隔离视觉误差的前提下，跑通并对比「纯 RL（Tang et al. 风格）」与「SFT + RL」在多步 3D 关系规划上的表现**，同时作为整篇论文的 **Planning Upper Bound**。

### 1. 训练与对比组设计（共 3 组，全部基于 Qwen3-VL-8B-Instruct + LoRA）
- **A0（Zero-shot 基线，已完成 `1169616`）**：
  - Greedy 成功率：$L=1$: 100%, $L=2$: 56%, $L=3$: 14%, $L=4$: 4%（总体 **43.5%**）。
  - 主要死因：$L=3, 4$ 第一步 86%–90% 选错（没先翻白面朝上），且 60% 的步数在推演颜色旋转时超 1024 token 截断。
- **A1（Pure Terminal-Reward GRPO —— 复刻 Tang et al. 2026 纯 RL 路线）**：
  - **不使用任何示范轨迹 SFT**，直接从基座模型出发，在训练集任务（剔除 200 个测试对后的其余 $96\times 95 - 200 = 8920$ 个状态对，从 $L \in \{2, 3, 4\}$ 采样）上跑多轮在线 GRPO。
  - **组采样与过滤**：每步采 16 个任务 $\times$ 组大小 $G=8$ 条多轮轨迹（Temperature 1.0，`max_tokens=768`），DAPO 过滤全成（8/8）或全败（0/8）的组。
  - **纯结果 + 步数效率奖励（无需特权中间监督）**：
    $$R_{\text{ep}} = \begin{cases} 1.0 - 0.05 \cdot (N_{\text{rounds}} - L^*) & \text{若回合结束到达目标终态} \\ -0.2 & \text{若发生截断或 JSON 解析失败} \\ 0.0 & \text{其它未完成情况} \end{cases}$$
    *(注：加入 $-0.05 \cdot (N_{\text{rounds}} - L^*)$ 的微小步数惩罚，是为了直接激励模型改掉“第一步先瞎翻到别的面再翻回白面”的绕路习惯，把轮数比从 $1.7\times$ 压向 $1.0\times$，并自然抑制超长啰嗦截断。)*
- **A2（BFS 轨迹 SFT + GRPO —— 检验示范暖启动对规划的作用）**：
  - 从 8920 个训练状态对中采样 2000 条 BFS 最优轨迹，用简洁模板合成 2–3 句标准空间推理（“目标与当前的窄带错位，且当前白面未朝上 $\to$ 第一步先将白面翻到朝上…”）+ 最优动作 JSON，做 1 个 epoch 的轻量 LoRA SFT（约 30 分钟），随后接同样的 GRPO。

### 2. 方案 A 的评估指标（在相同的 200 个测试任务上）
1. $L=1, 2, 3, 4$ 各层的 Greedy 成功率（目标：将 $L=3$ 从 **14% $\to$ 90%+**，$L=4$ 从 **4% $\to$ 85%+**）；
2. 成功回合的**平均轮数比 $N_{\text{rounds}} / L^*$**（目标：从 **1.71×–2.00×** 压到 **1.00×–1.10×**）；
3. 单步决策归因变化（`optimal` 比例 vs `suboptimal_legal` vs `truncated`）；
4. **Isaac Lab `Unified v4` 真实物理闭环验证**：将训好的 A1/A2 策略接进 `p2_bfs_oracle.py` 的 `ExternalGoalUnifiedRunner`，在 256 envs 真实物理仿真中跑完 200 个测试任务，确认符号训练策略在真实 60 Hz 物理控制器上的零损迁移（预期成功率与符号评估相差 $< 1\%$）。

## 四、方案 C 详细实验计划（视觉端到端 Map-then-Reason SFT + 闭环 GRPO）

如果执行方案 C，目标是**让 Qwen3-VL-8B-Instruct 直接看单张 `montage` 三视角拼贴图（无任何特权文本状态、无 SoM 数字贴标），自己完成「局部视角颜色识别 $\to$ 全局 3D 关系状态拼合 $\to$ 多步动作规划」**。

### 1. 阶段 C1：数据集构建与 Map-then-Reason 视觉 SFT（攻克 0.0% $\to$ 90%+ 细粒度感知）
- **图像数据源**：
  - 复用已采集的 `z1-main-job1163684`（1280 帧 $\times$ 5 相机）。其中 `z1_frames_v2.jsonl` 已按 Episode 严格划分为 `test`（96 个 episodes 抽出的 180 帧静止帧）和 `dev`（32 个 episodes）。
  - 为扩大训练集覆盖度并严格防泄露：用 `33_z1_capture.sbatch` 额外采集 32–64 个新种子 episodes（约 2500–5000 帧静止帧，T4 跑 10 分钟即可），全部转为 **P1 验证最优的 `montage` 单图格式（`c1 + s040 + s220` 裁剪放大拼贴）**。
- **三层递进式 Map-then-Reason SFT 格式（核心设计）**：
  为什么 P1 里 `montage` 的 `up` 有 0.900，但 `band` 只有 0.075，而贴了 `[1]/[2]` 的 `som` 却有 0.679？因为模型在没有引导时不会主动去每个视角里找「下层 2/3 主面 + 正上方 1/3 窄带」的配对。SFT 通过强制输出以下 JSON 结构，把 `som` 的空间注意力内化到模型权重里：
  ```json
  {
    "view_obs": {
      "c1": {"visible_sides": [{"base": "red", "top_strip": "blue"}, {"base": "magenta", "top_strip": "none"}]},
      "s040": {"visible_sides": [{"base": "green", "top_strip": "red"}]},
      "s220": {"visible_sides": [{"base": "blue", "top_strip": "yellow"}]}
    },
    "state": {
      "up": "blue",
      "front": "red",
      "strips_on_base": {"red": "blue", "green": "red", "yellow": "green", "blue": "yellow"}
    },
    "thought": "Target requires strips_on_base[red]=red (aligned) and up=green. Currently strips are shifted (+90 CW) and up=blue (not white). I must first reorient white to up.",
    "action": {"action": "reorient", "up": "white", "front": "red"}
  }
  ```
- **C1 阶段的两个消融对照**：
  1. *Direct-Action SFT*：`montage 图 + 目标 -> {"action": ...}`（不输出 `view_obs` 和 `state`，测试没有显式认知地图时 VLM 能否学会操作）；
  2. *Map-then-Reason SFT（主推）*：输出完整 `view_obs -> state -> thought -> action`。
- **C1 关口检验（跑在 `z1-mcq-v2` 180 帧 test 集 + 通用基准上）**：
  - 在 180 帧 test 集的 `montage` 图（无 SoM 贴标！）上，状态识别准确率从零样本的 **0.000** 提升至 **$\ge 0.85$**；
  - 重跑 `37_bench_vlm_eval.sbatch`（BLINK / MMStar / EmbSpatial），确认 LoRA 微调后通用空间推理分数波动在 $\pm 1.5$ 分以内（无灾难性遗忘）。

### 2. 阶段 C2：SFT 暖启动后的视觉多轮闭环 GRPO（含辅助奖励消融）
- **如何解决视觉 RL 采样慢的问题？（图像索引加速池 + Isaac Lab 真实物理验证）**
  - 在 P2.1 中我们已经证明：`Unified v4` 在 96 个离散状态之间的物理转移成功率是 **100.0%**！
  - 因此，在 GRPO 训练采样时，不需要让 H100 每一步都停下来等 T4 跑 60 步 Isaac Sim 渲染：我们可以从训练集里为全部 96 个离散状态预先建立 **「96 状态真实含手遮挡 `montage` 图像池」（每个状态存 15–30 张不同手指抓取姿态的真实渲染 `montage` 图）**。
  - 在 GRPO 的每一轮 $t$，当状态转移到 $(o_t, d_t)$ 时，环境直接从该状态的真实含手遮挡图像池中随机抽取一张 `montage` 图喂给 VLM！这样 **视觉多轮 GRPO 的采样速度与纯文本 GRPO 一样快（几毫秒一步）**，而模型看到的每一帧都是 100% 真实的 Isaac Sim 光追含手遮挡图像！
  - 训练完成后，在最终评估时，同时在 **「留出集图像池闭环」** 和 **「T4 实时 Isaac Sim + `Unified v4` 在线渲染闭环」** 上评测。
- **C2 奖励函数消融（论文核心消融点）**：
  - **C2-Terminal（纯结果奖励）**：只有回合结束到达目标终态时给 $R_{\text{ep}}$（同方案 A1）。
  - **C2-Grounded（带状态接地辅助奖励 $R_{\text{state}}$）**：
    $$R_{\text{total}} = R_{\text{ep}} + \lambda_{\text{state}} \cdot \frac{1}{N_{\text{rounds}}} \sum_{t=1}^{N_{\text{rounds}}} \mathbb{I}\big(\hat{s}_t = s_t^{\text{GT}}\big)$$
    每轮模型预测的 `"state"` 与真值一致额外给 $+0.2$ 奖励。这既能防止 RL 阶段为了刷动作奖励而胡乱输出状态 JSON（Language Drift），又能在长程失败回合中精确告诉模型“哪一步看错了图”。

## 五、选型建议：先做 A、先做 C，还是「A 与 C 联动」？

其实基于我们刚刚建好的管线，**方案 A 和方案 C 根本不是互斥的二选一，而是可以「共用同一套代码、在 1~2 天内一气呵成跑出完整 2×2 归因表」的递进关系**：

1. **为什么建议「先花半天跑完方案 A，紧接着跑方案 C」？**
   - **第一**，方案 A（`relational` 文本状态）和方案 C（`montage` 图像 $\to$ `relational` 状态 $\to$ 动作）的后半段（`state -> thought -> action`）**在数学和 JSON 格式上是 100% 同构的**！
   - **第二**，方案 A 是方案 C 不可或缺的 **无感知误差上界（Oracle Perception Upper Bound）**。审稿人看到方案 C 在视觉闭环上做到比如 82% 成功率时，一定会问：“剩下的 18% 是因为看图看错了，还是因为 8B 模型规划能力上限就只有这么多？”——有了方案 A 的数据，你的 **2×2 反事实矩阵** 和 **单步四象限归因（纯感知错 vs 纯规划错 vs 双重错）** 就严丝合缝了。
   - **第三**，利用上面设计的 **「96 状态真实含手遮挡 `montage` 图像池」**，方案 A 和方案 C 的 GRPO 训练器代码 **95% 完全相同**（唯一的区别是 User Prompt 里放的是 `Current State` 文本，还是 `Current Montage Image`）！

### 推荐执行顺序（最快今天就能看到第一批训练提升结果）：
1. **第一步（最快，2–3 小时出结果）**：在 `relational` 设定下跑通 **方案 A（A2 轻量 BFS 轨迹 SFT + A1/A2 GRPO）**，验证模型在 200 个测试任务上能否从零样本的 **43.5%（$L=3$: 14%, $L=4$: 4%）** 飙升到 **95%+（且轮数比压到 ~1.05×）**。
2. **第二步（无缝衔接，半天出结果）**：从 `z1-main-job1163684` 的非 test 回合构建 **Map-then-Reason 视觉 SFT 数据集与 96 状态 `montage` 图像池**，训出 **方案 C（C1 视觉 SFT + C2 视觉闭环 GRPO）**，并在 180 帧 Z1 测试集和 200 个多步闭环任务上出齐最终对比表！
