**问题拆分**

LLM 做闭环决策慢，有三个来源：

1. 自回归解码串行，每次决策要生成几十到几千 token。
2. 工程开销：网络往返、排队、过长的思维链、重试。
3. 结构性延迟：观测 → 推理 → 执行，决策总是基于旧观测，模型再快也存在。

下面六类方法各自针对其中一部分。

**本项目已有的相关数字**（Stage 1 任务，目标对 actor 隐藏；来源见 `Experiment Plan/RATE_SWEEP_PLAN.md`）

| 轴 | goal-4 | hand-8 |
|---|---|---|
| 刷新率 60 / 10 / 5 / 2 Hz（训练时带 hold） | 0.77 / 0.71 / 0.65 / 0.43 | 0.87 / 0.18 / 0.10 / 0.02 |
| 延迟 0 / 0.1 / 0.5 / 1 / 2 s（仅评估，60 Hz） | 0.77 / 0.64 / 0.39 / 0.26 / 0.16 | 0.87 / 0.003 / 0 / 0 / 0 |
| 量化 8 / 4 / 3 / 2 bit 每分量（仅评估） | 0.77 / 0.12 / 0.01 / 0.00 | 未测 |

数值是 Recovery。另外：expert rollout 上目标平均每 21.9 步变一次（2.7 Hz）；周期刷新把每回合成功数上限压到约 600/N。

## 一、解耦：慢模型不进高频环

大模型低频输出一个中间表示，小控制器高频闭环。各工作的差别在于中间表示是什么。

| 中间表示 | 文献 | 出处 | 要点 |
|---|---|---|---|
| 隐向量 | [FiS-VLA](https://arxiv.org/html/2506.01953v1) | NeurIPS 2025【已核对】 | 快模块嵌在慢 VLM 的末几层；报 117.7 Hz，快慢频率比 1:4，分块长度 8 |
| 隐向量 | [DuoCore-FS](https://arxiv.org/html/2512.20188v1) | 【预印本】 | 慢 1–3 Hz、快 25–30 Hz，用隐缓冲区耦合；训练时故意错开两路观测的时间戳 |
| 隐向量 | [NebulaVLA](https://www.alphaxiv.org/abs/2608.16503) | 【预印本】仅聚合站 | 约 10 Hz 的 System 2 配约 20 Hz 的 System 1 |
| 动作级 | [EMS](https://arxiv.org/pdf/2608.06434) | 【预印本】编号与标题对应有歧义 | 两个系统各自端到端出动作，只在动作层通信 |
| 稀疏长程意图 | [LiMA](https://www.alphaxiv.org/abs/2609.28431) | 【预印本】称 CoRL 2026，未核对 | 双手灵巧操作；慢模块给稀疏意图，快模块出手臂和手的动作分块 |
| 代价 / 约束 | [ReKep](https://arxiv.org/abs/2409.01652) | CoRL 2024【凭记忆】 | VLM 写关键点约束函数作代价，下层滚动优化；作者自己指出高频重跑 VLM 太贵 |
| 代价 | [CoRAL](https://roboticsproceedings.org/rss22/p054.pdf) | RSS 2026【已核对】 | LLM 塑造 MPPI 规划器的代价函数 |
| 控制器参数 | [LLM 调 MPC 参数（自动驾驶）](https://arxiv.org/pdf/2504.11514) | 【预印本】 | LLM 间歇调参，推理延迟不进固定频率的 MPC 环 |
| 语义规划 + RL | [HCRMP](https://arxiv.org/pdf/2505.15793) | 【预印本】 | 低频 LLM 加高频 RL，明确讨论 LLM 输出迟到 |
| 快慢两层智能体 | [DPT-Agent](https://arxiv.org/pdf/2502.11882v5) | 【预印本】 | Overcooked 上的实时人机协作 |
| 远端 + 机载 | [AsyncVLA](https://arxiv.org/html/2602.13476) | 【预印本】 | 导航；大模型在远端，机载轻量适配器高频修正，处理通信延迟 |

凭记忆补充，未检索：Helix、GR00T N1、Hi Robot、HiRT（隐向量或语言子任务接口）；Language to Rewards、VoxPoser、Code as Policies（代价或代码接口）。

**对 future work 的启发**

- 你的 rate sweep 给这张表补了一条定量依据：从 10 Hz 往下，目标级接口（goal-4）胜过所有动作级接口。这与"代价 / 约束 / 目标"一族的设计选择一致，而文献里很少有人在同一任务上把两族放在一起比。
- 没测过的一族是**学出来的隐向量接口**。可以加一个条件：高层编码器与学生策略端到端训练，瓶颈为 k 维，再在同样的刷新率下与 goal-4、hand-k 比。问题是"学出来的接口在低刷新率下更像目标还是更像动作"。
- DuoCore-FS 训练时错开观测时间戳。对应到你这里，是训练时随机化 hold 的相位和长度，而不是固定 N。这能回答"一个策略能否覆盖一段刷新率范围"，比每个 N 训一个策略更接近真实部署。
- EMS 的动作级通信相当于你的 hand-20。你的数据显示它在 60 Hz 下 Recovery 0.81，但 hand-8 在 10 Hz 已掉到 0.18，可以作为"动作级通信对刷新率敏感"的证据引用。

## 二、异步执行：承认延迟，边执行边推理

针对结构性延迟。前提是下层执行一段动作分块，上层在执行期间算下一段。

| 文献 | 出处 | 要点 |
|---|---|---|
| [RTC](https://arxiv.org/abs/2506.07339) | 【预印本】Physical Intelligence + UC Berkeley | 把新分块的生成当作修补：冻结推理期间已承诺执行的动作，其余部分补全；不需重训 |
| [REMAC](https://arxiv.org/pdf/2601.20130) | 【预印本】 | 训练时遮掉分块的一部分，推理无额外开销 |
| [VLASH](https://arxiv.org/html/2512.01031v2) | 【预印本】 | 模型以"推理结束时的未来状态"为条件；摘要称反应延迟最多降 11.8 倍 |
| [FutureRTC](https://arxiv.org/pdf/2607.24008) | 【预印本】 | 适配器从旧观测预测执行时刻的观测 |
| [FASTER](https://arxiv.org/html/2603.19199v1) | 【预印本】 | 缩短首个动作的输出时间 |
| [Acting While Understanding](https://arxiv.org/html/2606.15285v1) | 【预印本】 | 语义模块与动作生成异步；指出延迟主要来自语义模块 |
| [Understanding Asynchronous Inference Methods for VLA](https://arxiv.org/html/2605.08168) | 【预印本】 | 对比推理时 RTC、训练时 RTC、VLASH、A2C2；指出以往工作多数只测 ≤4 个控制步的延迟 |

凭记忆补充：ACT 的时间集成、Bidirectional Decoding。

**对 future work 的启发**

- **延迟下训练**是最直接的一步。你的 P1 延迟扫描是仅评估的，策略没见过延迟。hand-8 在 0.1 s（6 步）延迟下就归零，属于分布外失败还是接口本身不可用，现在分不开。在延迟下训练（固定延迟或随机化）能分开这两种解释。
- 对比论文说以往只测到 4 个控制步。你测到 120 步（2 s），范围大得多，可以在报告里作为差异点。前提是核对原文这句话。
- **意图分块**：你的 hold 是零阶保持，只发一个值再保持 N 步。Step 0 显示保持的 hand-k 在 20 Hz 下只能重建约 5% 的动作方差，因为 expert 接近 bang-bang 且抖动。替代方案是每次发未来 H 步的 hand-k 序列。这会增加每条消息的比特数，所以公平的比较是在相同 bit/s 下比"低维高频"与"分块低频"。
- **未来状态条件**（VLASH 思路）：已知延迟 d 时，高层针对预测的 t+d 时刻状态算意图。对 goal-4，延迟的主要伤害来自成功后目标已换而意图还是旧的。真实 LLM 规划器通常知道下一个子目标，可以提前发出；你的环境里目标是随机采样的，要测这一点需要让高层能看到下一个目标，这改变了任务的信息结构。

## 三、延迟感知与补偿

不消除延迟，让系统知道信息有多旧并据此行动。

| 文献 | 出处 | 要点 |
|---|---|---|
| [Reflex First, Reflect Later](https://arxiv.org/pdf/2506.07223) | 【预印本】 | 给缓存的计划打陈旧度分数，超阈值才重规划；在 HAZARD 上加了响应延迟类指标 |
| [Win Fast or Lose Slow](https://arxiv.org/html/2505.19481v1) | 【预印本】 | 延迟敏感任务的基准（高频交易、格斗游戏）；胜率随延迟下降先升后降，有帕累托最优点 |
| [Your LLM Agents are Temporally Blind](https://arxiv.org/pdf/2510.23853v2) | 【预印本】 | LLM 默认不考虑消息之间流逝的真实时间 |

凭记忆补充的经典控制方法：Smith 预估器；延迟 MDP，把尚未执行的动作队列并入状态；训练时延迟随机化。

**对 future work 的启发**

- **事件触发刷新**。目标平均 2.7 Hz 变一次，而周期刷新把成功数上限压到约 600/N。如果改为"成功后才刷新"，平均消息率仍是约 2.7 Hz，但陈旧时间接近零。在相同平均消息率下比较周期刷新与事件触发，可以把"消息率不够"和"刷新时机不对"分开。代价是需要一条上行通道，由下层报告"完成"。
- **把意图年龄作为观测**。给学生策略加一维"距上次刷新的步数"。策略可以学到在意图变旧时保守一些，例如先稳住方块。hand-8 在 10 Hz 保持下掉落率 62%，这一维也许能降低掉落。
- **用真实 LLM 延迟标定你的曲线**。Win Fast or Lose Slow 的思路是把延迟与决策质量放在同一张图上。你已经有 Recovery 对延迟的曲线：2 s 时 goal-4 只剩 0.16，而未优化的 LLM 调用常在 2–8 s。结论可以写成任务的目标变化率与高层决策率之比，而不是绝对的 Hz。
- 时间盲的发现提示：如果以后接真实 LLM 做高层，提示里要给时间戳和上次指令的年龄。

## 四、让模型本身更快

针对解码串行和每次决策的计算量。

| 文献 | 出处 | 要点 |
|---|---|---|
| [A Survey on Efficient VLA Models](https://arxiv.org/html/2510.24795v2) | 【预印本】2026-02 修订 | 分为高效模型设计、训练、数据采集 |
| [Efficient LVLM 推理综述](https://arxiv.org/html/2603.27960v1) | 【预印本】 | 视觉 token 压缩与 KV 缓存管理 |
| [VLA-Perf](https://www.arxiv.org/pdf/2602.18397) | 【预印本】 | VLA 延迟与吞吐的解析模型，覆盖异步与双系统 |
| 视觉 token 剪枝：FastV、EfficientVLA、SP-VLA、SpecPrune-VLA | 见综述，二手描述 | 按注意力或运动信息丢弃视觉 token |
| DEER-VLA | 见综述，二手描述 | 中间层挂轻量策略头，提前退出 |
| VLA-Cache | 见综述，二手描述 | 对静态图像块复用 KV 缓存 |
| [Adaptive VLA Inference](https://arxiv.org/pdf/2608.06434) | 【预印本】编号与标题对应有歧义 | 按环境难度选择模型大小 |

凭记忆补充：FAST 动作 tokenizer、OpenVLA-OFT 并行解码、流匹配动作头、推测解码、蒸馏与量化、专用推理硬件、本地部署去掉网络往返。

**对 future work 的启发**

- 这一类决定真实系统落在你刷新率轴上的哪一点。你的曲线可以反过来用：给定目标 Recovery，读出所需的最低刷新率，再对照这些方法能达到的频率。
- **用 token 计量接口**。量化结果显示 goal-4 每分量 8 bit 可用、4 bit 就崩，所以一条消息至少约 32 bit，对应几个 token。把接口成本写成 token/消息，乘以实测的 token/s，就得到某个模型可达的刷新率。这把"低维"的好处从维度换算成了时间。
- 量化扫描也是仅评估的。4 bit 崩溃可能同样是分布外问题，在量化下训练是与"延迟下训练"并列的补充实验。
- hand-8 的量化还没测，补上后才能在 bit/s 这一条轴上比较两种接口。

## 五、流式与并发的智能体工程

针对工程开销，多数不需要改模型。

| 文献 | 出处 | 要点 |
|---|---|---|
| [GhostShell](https://arxiv.org/pdf/2508.05298) | 【预印本】 | 生成中途解析函数调用，边生成边执行 |
| [Speculative Interaction Agents](https://arxiv.org/pdf/2605.13360) | 【预印本】 | 异步 I/O 加推测性工具调用；摘要称云端模型 1.3–1.7 倍、边缘模型 1.6–2.2 倍加速 |
| [AsyncReasoning](https://arxiv.org/pdf/2512.10931v2) | 【预印本】 | 用户输入、私有思考、公开输出三条流并发，免训练 |
| [Streaming LLMs 综述](https://arxiv.org/html/2603.04592v2) | 【预印本】 | 把输入输出同时连续的 LLM 形式化 |

其他工程手段：提示缓存、限制思维链长度、结构化短输出、事件触发而非定时调用、按难度路由到大小模型。

**对 future work 的启发**

- **渐进式消息**。流式输出意味着一条意图可以先到粗略部分、再到精细部分，下层先按前缀行动。对应的实验是把 goal-4 编码成先粗后细的比特流，测前缀可用性。你的量化结果（4 bit 已崩）提示粗前缀可能不够用，这个实验的预期收益不高，除非先做量化下训练。
- **推测执行**。高层预先算好"当前目标成功后"的下一条意图，成功事件一到立即下发。这与第三节的事件触发是同一个实验的两面。
- 如果报告的 future work 要写"接入真实 LLM"，这一节是实现清单，不产生新的科学问题。

## 六、离线化：运行时不调用 LLM

LLM 只出现在训练期或设计期，运行时的延迟问题不存在。

| 文献 | 出处 | 要点 |
|---|---|---|
| Eureka | ICLR 2024【凭记忆】 | LLM 写奖励函数，RL 训练策略 |
| [When LLM Reward Design Fails](https://www.alphaxiv.org/abs/2605.28918) | 【预印本】 | 把 LLM 奖励设计当作调试过程；稀疏奖励 RL |
| [The End of Reward Engineering](https://arxiv.org/pdf/2601.08237) | 【预印本】 | 多智能体；奖励生成的延迟占主导，建议模板和蒸馏的小奖励模型 |

**对 future work 的启发**

- 你的师生框架已经是半离线的：意图由冻结 expert 算出，不是 LLM。这一类指出另一个极端，即把高层完全蒸馏掉。可以作为讨论里的对照：当任务的目标变化率高于 LLM 能达到的决策率时，在线高层不成立，只能离线化或把目标序列预先下发。
- 新任务（原 M3 或技能切换）的奖励可以让 LLM 起草，但这改变奖励定义，与现有结果不可比，只适合全新任务。
- 技能切换试点与这一类相接：LLM 低频选技能，技能本身是离线训好的策略。这时"接口"变成离散的技能编号加参数，比特数极低，刷新率要求由技能持续时间决定。

## 七、汇总：按改动量排序的候选 future work

| 候选 | 来自 | 改动量 | 回答的问题 |
|---|---|---|---|
| 延迟下训练 goal-4 与 hand-8 | 二 | 小：训练时加延迟，评估已有 | 延迟敏感是分布外失败还是接口固有 |
| 量化下训练；补 hand-8 量化 | 四 | 小 | 接口的最低 bit/s |
| 意图年龄作为观测 | 三 | 小：观测加一维 | 策略能否对陈旧意图保守行动 |
| 事件触发刷新对周期刷新（等平均消息率） | 三、五 | 中：需要上行"完成"信号 | 消息率不足与刷新时机不对各占多少 |
| 随机化 hold 长度与相位训练 | 一 | 中 | 单一策略能否覆盖一段刷新率 |
| 意图分块（等 bit/s 比较） | 二 | 中：接口维度变为 k×H | 低维高频与分块低频哪个划算 |
| 学出来的隐向量接口 | 一 | 大：高层编码器端到端训练 | 学出的接口像目标还是像动作 |
| 真实 LLM 做高层 | 三、四、五 | 大 | 以上结论在真实延迟分布下是否成立 |

前三项都是在现有 M1 管线上加一个训练或观测选项，适合写进报告的 future work 并注明"现有评估脚本可直接复用"。
